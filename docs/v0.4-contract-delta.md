# v0.4.0-alpha.1 — generic R98 Alpha

This Alpha version combines the v0.3 public Full source with a reviewed generic R98 overlay. The QuantumNous New API module identity and AGPL attribution are retained. Historic release records are preserved. Start at the [fixed v0.4 version page](https://github.com/ginsonko/newapi-smart-router/releases/tag/v0.4.0-alpha.1) or [build from the pinned sources](build-v0.4.md). The version link is not a claim of publication, CI success or host certification; consult that version's assets, manifest and receipts for actual evidence.

## Implemented contract

| Area | Full host behavior | Porting responsibility |
|---|---|---|
| Core | Deterministic price/quality/capacity selection, cache-cost history, tier-price expressions, text/media recovery and image health | Supply immutable authorized host snapshots; core is not a gateway |
| Authorization and catalog | Catalog/pricing/group scope follows current user permissions; group and route prices remain distinct | Revalidate authorization after policy changes and at dispatch |
| Key memory | `tokens.routing_policy_memory` is a separate nullable TEXT column; fixed routing clears active `routing_policy` and keeps the remembered policy | Preserve omitted versus empty updates; never execute remembered policy directly |
| Image jobs | Durable job/attempt identity, frozen policy and authorized groups, per-attempt reservation/refund and terminal fallback | Commit accounting before another attempt; unknown provider acceptance is reconciliation-only |
| Health | Real image evidence, default one-hour window configurable through `image_failure_window_seconds`, independent threshold | Pending, content rejection, user rejection and synthetic probes do not become route failures |
| Media and quote | Price commitments, parameter pricing, owner-isolated task retrieval and retained request identity | Keep quote scope/revision, reservation identity and upstream task affinity |

The image health default in this Alpha version is 3600 seconds. Deployments can configure it between 1 and 86400 seconds through the existing settings path. No synthetic paid probe is introduced. An unavailable image route is not declared healthy just because time passed; real success supplies recovery evidence.

The memory column has no NOT NULL or DEFAULT requirement. An old worker continues to read the active policy only. A schema upgrade must precede a new writer; dropping the new column during rollback would discard saved preferences. New UI callers can explicitly clear memory with an empty value, while omitted memory preserves the prior policy. Runtime authorization is still evaluated against current permissions.

## Migration naming warning

`bin/migration_v0.3-v0.4.sql` is a historical upstream host script, not the Smart Router v0.4 upgrade; do not run it based on the coincidental filename. The new nullable `tokens.routing_policy_memory` column is created through the host's normal `AutoMigrate` path before new writers are enabled. Align Web and Worker to the same artifact before resuming work. Rollback retains the added column, memory and durable job/accounting data; it does not replay unknown upstream attempts. Follow the [schema upgrade and rollback steps](build-v0.4.md#schema-upgrade-and-rollback), not the old SQL filename.

## Four forms

- Full: complete generic host source, both frontend themes, worker and a Linux binary after the release checks pass.
- Bridge: trusted Hook contract and standalone validation library. No official upstream commit is certified; unknown or unverified hosts fail closed.
- Integration: read-only doctor, schemas, checklist and the same reference contracts. Host integration remains required.
- Parts: synchronized standalone reference code and conformance fixtures. Development Kit / Not runnable.

Bot relief and bot account endpoints, the private shop, courses, site-specific branding, runtime settings and production data are excluded. Public upstream payment/subscription features and previously published general commission code remain part of the reference host. Generic tenant accounting primitives are included because the quote/reservation/task settlement dependency chain consumes them; no tenant, reporting token, customer or channel configuration is shipped.

## Evidence boundaries

The conformance vectors are updated for the actual R98 contract: safe text exhausts unattempted eligible physical channels even when a legacy numeric cap is present; media retains its numeric cap; a side-effecting fallback requires an explicit trusted-host rejection grant, never an unknown acceptance result. Fresh proven success re-admits a route as normal without a second warming gate. Negative cap, committed-response, unknown-grant and state-bound cases remain, with additional positive vectors. A planner grant is not itself permission to resend a provider request: host outcome, reservation and refund checks must authorize it.

The final memory UI is the default theme. The classic theme remains buildable with its existing routing UI; it does not add the default theme's remembered-draft editor. Full keys-directory lint has pre-existing style findings; the changed memory helper, export and drawer receive a separate required lint run without rule suppression.

Local tests and reproducible builds establish the candidate artifact only. They do not establish a live upgrade, paid-provider settlement, production deployment, three-database lifecycle acceptance, remote CI, signed images or compatibility with an arbitrary New API fork. Those remain distinct acceptance obligations. Read the generated receipts and checksum manifest for the exact build result.
