# v0.2 Smart Router contract delta

Status: `Public Alpha candidate`
Target: `v0.2.0-alpha.1`
Reference behavior: accepted NewAPI R39 snapshot

This document adds the post-v0.1 contracts without replacing the original
manual. It separates reusable core behavior from host integration behavior so
that compilation is never mistaken for Full parity.

## 1. Effective route price

The planner no longer assumes that every route can be compared by a group
ratio alone. A `RoutePrice` contains a billing mode, billing unit, comparison
class and fixed-point score.

For NewAPI token pricing:

```text
resolved_model_base = explicit_group_model_base, when explicitly configured
resolved_model_base = real_global_model_base, when inherited
route_score = resolved_model_base * effective_group_ratio
```

An explicit group-model price replaces the global model base. It is not a
multiplier on top of that base. The effective group ratio is applied exactly
once. Missing inherited model prices are unresolved, not synthetic `1x`.

Only routes with the exact same `comparison_class` may be ordered by
`score_ppm`. Token, per-request, per-second, fixed-duration and expression
prices must remain in separate classes unless the host can prove identical
cost shape. This routing score never replaces actual reservation, usage or
settlement data.

Normative schema: [`route-price.schema.json`](../parts/spec/route-price.schema.json).

## 2. Replay and dispatch classes

| Planner class | Initial smart route | Cross-route fallback | Synthetic probe |
|---|---:|---:|---:|
| `safe_text` | Yes | Sequential eligible channels | Contract-dependent |
| `safe_image` / `safe_video` / `safe_audio` | Yes | Only after proven non-acceptance | No |
| `side_effecting` | Exactly one route | Never after dispatch starts | No |
| `state_bound` | No | No | No |
| `unsupported` | No | No | No |

`store:true`, `background:true` and hosted tools are side-effecting when no
state-bound signal exists. `previous_response_id`, conversation identity and
upstream-bound files are state-bound and take precedence. A state-bound request
is rejected before opening an upstream connection.

Disabling the host attempt-limit switch grants exhaustive fallback only to
`safe_text`. Attempts remain serial, every retry re-runs authorization,
group/Key scope, exclusion, price, health, capacity, capability, context and
credential filters, and each physical channel is tried at most once. The old
numeric `1..8` limit remains available when the switch is enabled.

The pure core decides whether another eligible route may be selected. The host
must record the physical channel before dispatch and enforce the post-dispatch
single-send fence.

## 3. Exact endpoint and adapter fence

The route catalog is authoritative for canonical model, exact endpoint and
capability fingerprint. An adapter-local endpoint allowlist may only intersect
and narrow that contract. It must never make an unsupported endpoint eligible.

`convert_request_failed` is eligible for another route only when conversion
failed before upstream dispatch. A conversion error after dispatch is not a
pre-dispatch fallback signal.

## 4. Semantic success and commit

HTTP 200 alone is not success. The exact adapter must validate transport,
protocol and business semantics. Empty or pseudo-success responses may be
classified as failures even with HTTP 200.

Non-streaming responses stay buffered until semantic validation. Streaming
responses may switch only before the first committed business event. SSE
comments, heartbeats and usage-only blocks do not by themselves create a valid
business response. Once committed, the current stream terminates on failure
and never splices output from another route.

The R39 Full reference snapshot contains the host implementation and focused
tests for these behaviors. Other hosts still need their own adapter fixtures
and Bridge evidence; the schema alone is not certification.

## 5. Recovery closure

A successful result resets the current outage episode. A warming route with
fresh success evidence may re-enter candidate selection for every strategy
without a second fixed recovery gate. Expired evidence, authorization, price,
capacity and replay constraints still apply.

Synthetic price evidence must not train cache-economy learning or trigger an
affinity switch. Real inherited and explicit prices can participate only when
their comparison classes match.

## 6. Runtime version contract

The serving Web process and dedicated Smart Router Worker must run the same
immutable binary and protocol revision. A mixed-version pair can publish stale
catalog, health or recovery semantics into shared state and is a release
blocker. Deployment acceptance must compare full artifact hashes, not only
version labels.

## 7. What each release form receives

| Form | v0.2 delivery | Host work still required |
|---|---|---|
| Full compatibility distribution | R39 source snapshot, frontend, Worker and host tests | Run exact release gates for the target environment |
| Certified Bridge Add-on candidate | Core, schemas and stricter Hook contract | Certify one exact host commit and every critical Hook |
| Custom Fork Integration Kit | Read-only doctor, semantic checklist and vectors | Implement trusted host boundaries and prove them |
| Agent Parts Kit | Reference core, RoutePrice schema, invariants and vectors | Build and test a host implementation; kit is not runnable |

Sidecar Lite remains an experimental appendix. It is not a fifth full-parity
form and cannot provide trusted per-Key billing, commit, task acceptance or
same-process dispatch guarantees by itself.

## 8. Preserved contracts

The update does not change ordinary NewAPI billing formulas, actual usage
settlement, refunds, fixed-Key behavior, media acceptance fences, user scope,
health/capacity separation or role-safe logging. A port that changes those
contracts to make routing easier is non-conformant.
