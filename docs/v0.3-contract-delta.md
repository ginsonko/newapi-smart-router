# v0.3 Smart Router contract delta

Target: `v0.3.0-alpha.1`

This document is an additive public description of the R52 Smart Router
contract. It does not certify a generic New API fork and does not change host
billing formulas.

## 1. Evidence and pricing

The planner may consume a bounded, read-only `ActualInputCostSnapshot` with
actual input tokens, cache-hit tokens, evidence age, upstream namespace and
confidence. It uses that evidence only to order candidates. Reservation,
settlement, refund and other site-specific ledger code must continue to consume the host's
frozen route-price and usage receipt.

Effective route price is resolved once:

```text
explicit group-model base -> that explicit base
inherit -> real global model base
effective comparison     -> resolved base × effective group ratio
```

No synthetic `1x` is invented when the global price is missing. Token,
per-request, per-second, fixed-duration and tiered prices have separate
comparison classes. A route is statically comparable only when request shape,
unit and cost evidence match.

## 2. Multimodal discovery and identity

The host may aggregate authorized text, image, video and audio models for a
Smart Key at `/v1/models`. Discovery is an authorization-preserving view, not
a union of every channel in the database. Cross-group routing requires exact
canonical model equality or an explicit host mapping, plus matching endpoint
and capability fingerprints. Similar strings alone never qualify.

Media price and capability snapshots describe reference assets, duration,
output count, audio and asynchronous acceptance. A task that may already have
been accepted is not replayed merely because the downstream connection ended.

## 3. Error and replay behavior

Before semantic commit, replay-safe text may serially exhaust all remaining
eligible physical channels, once each. Rate limit, pending/capacity,
overloaded, upstream 5xx, timeout, transport and unknown upstream errors are
route failures eligible for that recovery boundary. Unknown errors are health
neutral. `side_effecting` dispatch, state-bound requests, media acceptance
unknown, background work, hosted tools and committed streams remain single-send.

User format, quota, content-safety, session-state and client-cancel outcomes
are terminal and are not blindly retried. The final error is bounded,
redacted, includes attempt count and request ID, and can be localized by the
host.

## 4. UI metadata

Group colors and same-color clustering are presentation metadata. Within a
color cluster, the host may order groups by effective group ratio. These values
must not alter RouteID, authorization, health, price resolution or billing.

## 5. Evidence required by form

| Form | v0.3 evidence | Boundary |
|---|---|---|
| Full | isolated source assembly, two frontend builds, core/host tests, archive and secret scans | exact reference host only |
| Bridge | `bridge-spi-v1alpha3`, Hook and Web/Worker digest tests | exact host commit not yet certified |
| Integration | doctor, manifest, schema, vectors, multimodal and error tests | host Hook work remains required |
| Parts | synchronized core, media/cost modules and vectors | development kit, not runnable |

The release remains Alpha/Pre-release. Stable requires the previously listed
database, lifecycle, external-site, signed-image and remote-build gates.
